  <action>
Create `supabase-rls-policies.sql` at the project root. This is the main migration file. Structure it as follows:

**Header comment block** explaining:
- This file enables RLS and deploys policies for all 11 tables
- Must be run AFTER supabase-rls-indexes.sql
- Must be run AFTER supabase-rls-audit.sql (to check for stale policies)
- Each table's ENABLE + policies are wrapped in BEGIN/COMMIT for atomicity (SEC-05)
- SEC-04 note: drawings are stored as base64 in responses.answers JSONB — no Supabase Storage buckets exist, so responses RLS covers drawing data

**Section 1: user_sessions table** (Pattern 3 from RESEARCH.md)
- `ALTER TABLE public.user_sessions ENABLE ROW LEVEL SECURITY;`
- SELECT policy: `user_id = (SELECT auth.uid())`
- INSERT policy: `user_id = (SELECT auth.uid())`
- No UPDATE/DELETE needed
- Wrap in BEGIN/COMMIT

**Section 2: sessions table** (Pattern 2 from RESEARCH.md)
- `ALTER TABLE public.sessions ENABLE ROW LEVEL SECURITY;`
- SELECT policy: `player1_user_id = (SELECT auth.uid()) OR player2_user_id = (SELECT auth.uid())`
- INSERT policy: `player1_user_id = (SELECT auth.uid())`
- UPDATE policy: same OR condition in both USING and WITH CHECK
- No DELETE needed
- Wrap in BEGIN/COMMIT
- IMPORTANT: Deploy user_sessions FIRST because session-scoped policies on other tables depend on user_sessions being queryable

**Section 3: Standard session-scoped tables** (Pattern 1 from RESEARCH.md)
For each of these 8 tables: `responses`, `profiles`, `deep_dive_responses`, `shared_items`, `love_notes`, `predict_partner`, `finish_sentence`, `hot_takes`
- `ALTER TABLE public.{table} ENABLE ROW LEVEL SECURITY;`
- Single FOR ALL policy named "partners access own session"
- USING: `session_id IN (SELECT session_id FROM user_sessions WHERE user_id = (SELECT auth.uid()))`
- WITH CHECK: same condition
- Each table wrapped in its own BEGIN/COMMIT block

**Section 4: reactions table** (Pattern 4 from RESEARCH.md)
- `ALTER TABLE public.reactions ENABLE ROW LEVEL SECURITY;`
- Separate SELECT, INSERT, UPDATE, DELETE policies (4 policies)
- All use the same session_id subquery through user_sessions
- Wrap in BEGIN/COMMIT

CRITICAL rules:
- Every `auth.uid()` MUST be wrapped as `(SELECT auth.uid())` for initPlan optimization (SEC-02)
- Every INSERT/UPDATE policy MUST have WITH CHECK clause (not just USING)
- Use `TO authenticated` on all policies (not `TO public`)
- Use the exact table name `love_notes` (NOT love_note_games/love_note_guesses)
- Add a SQL comment before each section identifying which tables and which pattern
- Add a final comment noting SEC-04: "Drawing data is protected by the responses table policy above (app stores drawings as base64 in responses.answers JSONB, not in Supabase Storage)"
