<task type="auto">
  <name>Task 1: Make join flow atomic and reject full sessions</name>
  <files>src/pages/JoinPage.jsx, src/pages/HomePage.jsx</files>
  <action>
**JoinPage.jsx changes:**

1. In `handleJoin()`, replace the unconditional UPDATE with a conditional one that only succeeds if the slot is still empty:
```javascript
const { data, error: joinError } = await supabase
  .from("sessions")
  .update({
    player2_name: displayName,
    player2_user_id: user?.id || null,
  })
  .eq("id", sessionId)
  .is("player2_user_id", null)  // atomic guard — only update if slot is empty
  .select()
```
After the update, check if `data` is null or empty array. If no rows were updated (slot was already taken), show an error: "this session was just claimed by someone else — refresh to see the current state". Do NOT proceed with user_sessions insert or navigation.

2. In the `alreadyJoined` render block (around line 110-128), **remove** the "open the notebook anyway" button entirely. Replace it with a message-only view:
- Keep the "two's company!" heading
- Change the message to: "this notebook already has two people writing in it"
- Add a "go home" button that navigates to "/" instead of into the vault
- Do NOT set sessionId/playerName/playerId context — the user has no access to this session

3. Also update `fetchSession` to select `player2_user_id` in addition to `player1_name, player2_name`, so the already-joined check can consider both fields (a session could have player2_user_id set but player2_name still null in edge cases).

**HomePage.jsx changes:**

4. In `autoJoin()` (around line 187-195), replace the unconditional UPDATE with the same conditional pattern:
```javascript
const { data: updatedRows, error: joinError } = await supabase
  .from("sessions")
  .update({
    player2_name: displayName,
    player2_user_id: user.id,
  })
  .eq("id", session.id)
  .is("player2_user_id", null)  // atomic guard
  .select()
```
If `updatedRows` is null or empty (race lost), fall back to `autoCreate()` with an appropriate error message like "that session was just claimed — we started a fresh one for you".

Do NOT use `.single()` on these update calls — use `.select()` and check the array length. `.single()` throws on zero rows which would need try/catch; checking array length is cleaner.
  </action>
