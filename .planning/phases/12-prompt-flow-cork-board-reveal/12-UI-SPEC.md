## Page 1: Prompt Flow (`/daily-photo-section/:sessionId/:sectionId`)

### Purpose

Guides the current user through 3 sequential photo prompts for the selected section. Each prompt is answered one at a time — the next prompt is only shown after the current one is submitted. After all 3 are submitted, the page transitions to the waiting screen.

### Route Parameters

- `:sessionId` — current session
- `:sectionId` — matches a `photoSections` entry ID (e.g. `'morning-routine'`)

### Layout

Single-column `.page` container. Structure from top to bottom:

1. `<PageGuide pageKey="dailyPhotoSection" />`
2. `<PageDoodles seed={12} />`
3. `<motion.div initial={{ opacity: 0, y: 15 }} animate={{ opacity: 1, y: 0 }}>`
4. Header block (section title + emoji)
5. Step indicator (3 dots)
6. Progress bar (3-step crayon fill)
7. Active prompt area (PhotoCaptureInput component)
8. OR: Waiting screen (if user submitted all 3, partner not done)

### Header Block

```
[ section.emoji 28px ]  [ section.title        ]
                         [ Prompt {N} of 3      ]
```

- Section emoji: 28px, `marginRight: 10`
- Section title: Caveat 1.25rem weight 600, `var(--text-primary)` — matches section card title size
- "Prompt N of 3" label below title: Patrick Hand 0.875rem, `var(--text-secondary)`, line-height 1.4
- Header container: `display: flex`, `alignItems: center`, `marginBottom: 16`

### Step Indicator (3 dots)

Three dots showing progress through the 3 prompts.

```
● ● ○    (prompt 1 done, prompt 2 done, prompt 3 not yet)
```

- Container: `display: flex`, `gap: 8`, `justifyContent: center`, `marginBottom: 8`
- Each dot: circle, 10px diameter
- Completed step dot: `background: var(--accent-coral)`, `opacity: 1`
- Active step dot: `background: var(--accent-coral)`, `opacity: 1`, with a 2px `box-shadow: 0 0 0 2px var(--bg-paper), 0 0 0 4px var(--accent-coral)` ring — visually distinguishes current prompt from completed ones
- Remaining step dot: `background: var(--border-pencil)`, `opacity: 0.6`

### Progress Bar

Crayon-fill bar identical to the existing `.progress-bar-track` / `.progress-bar-fill` CSS classes in index.css.

- Track: full width, 10px tall, `.progress-bar-track` className
- Fill: `.progress-bar-fill` className, width = `{completedCount / 3 * 100}%`
- Container: `marginBottom: 24`

### Active Prompt Area

Renders `<PhotoCaptureInput>` with the current prompt's data.

Props passed to PhotoCaptureInput:
- `prompt` — `section.prompts[currentPromptIndex].text`
- `onPhotoSubmit` — handler that stores the path + caption and advances to next prompt
- `sessionId`, `playerId`, `sectionId`, `promptIndex` — forwarded from page state/params

No wrapping card around PhotoCaptureInput — it renders directly inside the `.page` container. The component's own polaroid frame and torn-paper caption handle the visual containment.

### Prompt Transition Animation

When a prompt is submitted and the next prompt loads, use Framer Motion `AnimatePresence` with `mode="wait"`:
- Exit: `animate={{ opacity: 0, x: -20 }}`, `exit={{ opacity: 0, x: -20 }}`
- Enter: `initial={{ opacity: 0, x: 20 }}`, `animate={{ opacity: 1, x: 0 }}`
- Duration: default (0.2s ease)

This gives a left-to-right slide as each prompt is completed, matching the existing quiz page question-advance pattern.

### Error Handling (prompt flow)

- Upload error: surfaced by PhotoCaptureInput's own inline error (Patrick Hand 0.875rem, `var(--accent-coral)`, `textAlign: center`, `marginTop: 8`) — page does not add a second error layer
- Section not found (bad sectionId): render a centered error message in Patrick Hand 1rem, `var(--accent-coral)`, with a "go back" link — navigates to `/daily-photos/:sessionId`

### Waiting Screen

Shown after the user submits all 3 prompts and the partner has not yet finished. Replaces the prompt area entirely — the header and progress bar stay visible (all 3 dots filled).

```
[ ☀️ section.emoji (32px) ]
[ Waiting for {partnerName}... ]
[ They're still working on their photos. Come back when you're both done! ]
[ "check back" button ]
```

- Container: `.glass` className, `padding: 24px`, `textAlign: center`, `marginTop: 16`
- Emoji: 32px, `marginBottom: 12`
- Heading: Caveat 1.25rem weight 600, `var(--text-primary)`
- Body: Patrick Hand 1rem, `var(--text-secondary)`, `lineHeight: 1.5`, `maxWidth: 280`, `margin: 8px auto 16px`
- "Check back" button: `.btn .btn-secondary` className, label "check back" — triggers a fresh poll of partner's completion state without page reload

Waiting screen polls the partner's completion state every 5 seconds (via `useRealtimeSync` hook with `pollingEnabled: true`). When partner completes, auto-navigates to the reveal page.

## Data Shape: Photo Answers

Phase 12 needs to read and write per-player, per-prompt photo answers. The data lives in the `responses` table.

### Storage Schema

Each player's photo answers for a section are stored as a single `responses` row:

```
session_id: sessionId
pack_id:    'daily-photo-section'
player_id:  playerId  ('player1' or 'player2')
answers: {
  sectionId: 'morning-routine',
  photos: [
    { promptIndex: 0, path: 'sessionId/player1/morning-routine_0.jpg', caption: 'my coffee' },
    { promptIndex: 1, path: 'sessionId/player1/morning-routine_1.jpg', caption: '' },
    { promptIndex: 2, path: 'sessionId/player1/morning-routine_2.jpg', caption: 'the chaos' },
  ],
  completedAt: '2026-04-01T09:00:00Z'  // set when all 3 prompts submitted
}
```

Unique constraint: `(session_id, pack_id, player_id)` — same as all feature tables. Use `upsert` on conflict.

### Completion Detection (GATE-04)

Both partners are done when BOTH rows exist with `answers.completedAt` set for the same `sectionId`. The reveal page queries both player rows and checks this before rendering the cork boards.

When the current user submits their last (3rd) photo, the prompt flow page also updates the shared `daily-photo-challenge` gate state in `responses` (pack_id: `'daily-photo-challenge'`, player_id: `'shared'`):
- Sets `inProgressSectionId: null`
- Sets `completedSections[sectionId]: ISO_TIMESTAMP`
- Sets `lastCompletedAt: ISO_TIMESTAMP`

This is the same gate state the hub page reads.

## Interaction Contracts

### Prompt Flow — Photo Submission

1. User opens a section from the hub (section is `in-progress` in gate state)
2. Page loads with `currentPromptIndex: 0` (the 3rd already-submitted prompt index if re-entering mid-flow)
3. User interacts with `PhotoCaptureInput` for the current prompt
4. On `onPhotoSubmit(path, caption)` callback:
   - Upsert the `responses` row with the new photo appended to `answers.photos`
   - Advance `currentPromptIndex` by 1
   - If index was 2 (last prompt): set `completedAt`, update gate state, show waiting screen
5. Re-entering flow mid-way (user closes and re-opens): read existing `answers.photos` array to resume at the correct index — do NOT re-show already-submitted prompts

### Prompt Flow — Back Navigation

- No explicit "back" button on the prompt flow page
- Browser back / swipe back: navigates to hub — acceptable, does not break gate state since `inProgressSectionId` is still set
- If user navigates away and returns, they re-enter at the correct prompt index

### Reveal Page — Photo Loading

- All 6 signed URLs (3 prompts × 2 players) fetched in parallel via `Promise.all`
- `expiresIn: 3600` (1 hour) — standard for viewing
- If a URL fails, show the error state for that slot: a dashed placeholder with "photo unavailable" text in Patrick Hand 0.875rem, `var(--text-light)`, centered

### Reveal Page — Re-entry

The reveal page is accessible any time after both partners complete the section. Hub page routes completed sections to this page. No restrictions on how many times it can be viewed.

### Realtime Sync (Waiting Screen)

The waiting screen on the prompt flow page subscribes to the `responses` table for this session via `useRealtimeSync`:

```js
useRealtimeSync({
  table: 'responses',
  sessionId,
  onUpdate: checkPartnerDone,  // useCallback-wrapped
  channelPrefix: 'prompt-flow-wait',
  pollingEnabled: isWaiting,
  pollingInterval: 5000,
})
```

When `checkPartnerDone` detects the partner row has `completedAt` set, auto-navigate to the reveal page:
`navigate('/daily-photo-reveal/' + sessionId + '/' + sectionId)`
