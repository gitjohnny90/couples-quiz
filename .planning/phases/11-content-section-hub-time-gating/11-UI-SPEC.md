## Page 1: VaultPage Entry Card

The Daily Photo Challenge card slots into the existing vertical list of quiz type cards in VaultPage. It uses the same `.glass` card pattern and framer-motion stagger pattern as the five existing cards (Multiple Choice, Deep Dive, etc.).

### Card Anatomy

```
[ 📷 emoji (28px)  ]  [ Daily Photos              ] [ progress indicator ]
                       [ answer 3 prompts together   ]
                       [ once a day                  ]
```

- Left: 28px camera emoji (`📷`) — matches size of existing card emoji icons
- Middle: title (`Daily Photos`) in Caveat 1.25rem weight 600, description in Patrick Hand 0.875rem color `var(--text-secondary)`, line-height 1.4
- Right: conditional indicator (see states below)
- Card: `.glass` className, `padding: 16px`, `cursor: pointer`, `transform: rotate(0.2deg)` (slight rotation for notebook feel)
- Framer Motion: `initial={{ opacity: 0, y: 8 }}`, `animate={{ opacity: 1, y: 0 }}`, delay `0.6` (stacked after the existing 5 cards at delays 0.1–0.5)
- `role="button"`, `tabIndex={0}`, `onKeyDown` Enter/Space handler — matches VaultPage accessibility pattern

### VaultPage Card States

| State | Right indicator copy | Right indicator style |
|-------|---------------------|-----------------------|
| Never started | `start photos →` | Patrick Hand 1rem, `var(--text-light)` |
| In progress (sections started but not all done) | `{N}/15` above `sections` label | Caveat 1.25rem weight 700, `var(--accent-coral)` for number; Patrick Hand 0.875rem `var(--text-light)` for label |
| All 15 complete | `15/15` above `done` label | Caveat 1.25rem weight 700, `var(--accent-sage)` for number; Patrick Hand 0.875rem `var(--text-light)` for label |

Card description copy:
- Default: "answer 3 photo prompts together — once a day"

## Page 2: Section Hub (`/daily-photos/:sessionId`)


- h1: Caveat 2rem weight 700, `var(--text-primary)` — matches VaultPage / VisionPage h1 exactly
- Subtitle: Patrick Hand 1rem, `var(--text-secondary)`, line-height 1.5, maxWidth 340, centered
- Bottom margin on header block: 16px

### Gate Status Banner

Visible only when `gateState === 'frozen'` (a section was completed today, no new section can start until 6am tomorrow).

```
[ ⏰  Come back tomorrow! ]
[ You finished a section today. New sections unlock at 6am. ]
```

- Container: inline styles — `background: rgba(212, 168, 67, 0.12)`, `border: 1.5px solid rgba(212, 168, 67, 0.3)`, `borderRadius: 4px`, `padding: 12px 16px`, `marginBottom: 16px`

- Heading line: Caveat 1.25rem weight 600, `var(--accent-mustard)`
- Body line: Patrick Hand 1rem, `var(--text-secondary)`, `marginTop: 4px`

### Completion Summary Line

Always visible below the banner (or below header if no banner). Shows aggregate progress.

Format: `{N} of 15 sections complete`
- Patrick Hand 1rem, `var(--text-secondary)`, `textAlign: center`, `marginBottom: 16px`
- When N > 0: the number N is colored `var(--accent-sage)`, weight 600, font Caveat

## Section Card Design

15 section cards rendered in a single-column list. Each card has one of four states.

### Shared Card Structure

```
[ left accent stripe (4px wide) ]  [ emoji (24px) ]  [ title              ] [ right badge ]
                                                      [ description 0.875rem ]
```

- Card: `.glass` className base
- Left accent stripe: `position: absolute; left: 0; top: 0; bottom: 0; width: 4px; borderRadius: '3px 0 0 3px'` — color varies by state (see below)
- `padding: '16px 16px 16px 20px'` (20px left to clear the 4px stripe — 4px stripe + 16px pad)
- Title: Caveat 1.25rem weight 600, `var(--text-primary)` (or `var(--text-light)` when locked)
- Description: Patrick Hand 0.875rem, `var(--text-secondary)` (or `var(--text-light)` when locked), line-height 1.4
- Emoji: 24px, left-aligned, `flexShrink: 0`

### Card States

**1. Available** (can be selected now — gate is open, no active section in progress)
- Left stripe: `var(--accent-coral)` (#E88D7A)
- Background: `var(--bg-card)` (#FFFDF7)
- Title color: `var(--text-primary)` (#3D2C2C)
- Right badge: none — no indicator
- Hover: `var(--bg-card-hover)` (#FFF5E9), `transform: rotate(-0.3deg)` (matches .option-btn hover pattern)
- `cursor: pointer`, `role="button"`, `tabIndex={0}`, `onKeyDown` Enter/Space

**2. Active** (currently in progress by this user — has been selected, not yet completed)
- Left stripe: `var(--accent-coral)` (#E88D7A)
- Background: `rgba(232, 141, 122, 0.06)` (very light coral tint)
- Right badge: `In Progress` — pill shape, `background: rgba(232, 141, 122, 0.15)`, `color: var(--accent-coral)`, Patrick Hand 0.875rem, `padding: 2px 8px`, `borderRadius: 10px`
- `cursor: pointer`

**3. Locked** (gate is closed — either frozen after completion, or another section is active)
- Left stripe: `var(--border-pencil)` (#D4C4B0)
- Background: `rgba(168, 152, 136, 0.06)` (subtle locked tint)
- Title color: `var(--text-light)` (#A89888)
- Description color: `var(--text-light)` (#A89888)
- Emoji: `opacity: 0.4`
- Right badge: `🔒 locked` — padlock emoji at 16px + "locked" text in Patrick Hand 0.875rem, `color: var(--text-light)`
- `cursor: default`, `aria-disabled="true"`, no click handler
- Sub-text below description (when frozen): Patrick Hand 0.875rem, `var(--text-light)`, italic — "unlocks at 6am"

**4. Completed** (both partners have finished this section)
- Left stripe: `var(--accent-sage)` (#7CAE7A)
- Background: `rgba(124, 174, 122, 0.06)` (very light sage tint)
- Title color: `var(--text-primary)` (#3D2C2C)
- Right badge: `✓ done` — pill shape, `background: rgba(124, 174, 122, 0.18)`, `color: var(--accent-sage)`, Patrick Hand 0.875rem, `padding: 2px 8px`, `borderRadius: 10px`
- `cursor: pointer` — tapping a completed section navigates to its cork board reveal (Phase 12 route, not yet built — stub with `navigate()` call that does nothing in Phase 11)

### Card Rotation

Cards have alternating slight rotations to match the notebook feel:
- Odd-indexed cards: `transform: rotate(-0.3deg)`
- Even-indexed cards: `transform: rotate(0.25deg)`
- Locked cards: no rotation (`transform: none`) — visually de-emphasized
- Completed cards: `transform: rotate(0.15deg)` — subtle, settled

## Time-Gating Logic Contract

These states are computed client-side from Supabase data. The executor uses this to implement `useDailyPhotoGate` or equivalent logic.

### Gate States

| State ID | Condition | Hub Behavior |
|----------|-----------|--------------|
| `open` | No section completed today AND no section currently active | All incomplete sections are `available` |
| `active` | A section has been started but not yet completed by current user | The in-progress section is `active`; all others are `locked` |
| `frozen` | A section was completed today (both partners done, or current user done and storing timestamp) | All sections are `locked`; gate banner visible with mustard color treatment |
| `unlocked` | Frozen state AND current time >= 6am the next day | Same as `open` for remaining sections; completed sections stay `completed` |

### 6am Unlock Computation

- Completion timestamp stored in DB (see Phase 11 plan — `daily_photo_sessions` table or similar)
- Client-side: compare `Date.now()` against `nextUnlockAt` (6am local time the day after last completion)
- "6am" is local device time — no timezone server logic in Phase 11
- The hub page re-checks gate state on mount and on window focus (`visibilitychange` event)

### Section Lock Logic (GATE-03)

- When user taps an available section card and navigates away to the prompt flow (Phase 12):
  - A DB record is written indicating this session + player is in-progress on this section
  - All other sections render as `locked` until the in-progress section is completed or abandoned
  - Phase 11 does not implement the abandonment flow — that is Phase 12 scope

## Interaction Contracts

### VaultPage Entry Card

- Tap anywhere on the card navigates to `/daily-photos/:sessionId`
- Keyboard: Enter or Space triggers navigation (matches all other VaultPage cards)
- Card does not show a loading state — navigation is immediate

### Section Hub Card Tap

**Available state:**
- Tap navigates to `/daily-photo-section/:sessionId/:sectionId` (Phase 12 route)
- In Phase 11 this route does not yet exist; the navigate call is written but lands on a 404/stub page — this is acceptable for Phase 11 scope
- No confirmation dialog — user simply picks a section

**Locked state:**
- Tap does nothing — `cursor: default`, no `onClick`
- Screen readers: `aria-disabled="true"`, `aria-label="{title} — locked"`

**Completed state:**
- Tap navigates to `/daily-photo-reveal/:sessionId/:sectionId` (Phase 12 route — also a stub in Phase 11)

**Active state:**
- Tap navigates to the in-progress prompt flow (same Phase 12 route, section already started)

### Gate Banner

- Not tappable — informational only
- No dismiss button — disappears when gate state transitions to `unlocked`

### Framer Motion

- Hub page entry: `initial={{ opacity: 0, y: 15 }}`, `animate={{ opacity: 1, y: 0 }}` on the main content wrapper (matches VaultPage / VisionPage)
- Section cards: stagger `delay: index * 0.04` — subtle cascade as cards render, does not exceed 0.6s total
- Gate banner: `initial={{ opacity: 0, y: -8 }}`, `animate={{ opacity: 1, y: 0 }}` spring entry

### Accessibility

- Hub h1 present on page (one per page — no duplicate h1)
- Section cards: `role="button"`, `tabIndex={0}`, `onKeyDown` Enter/Space for available and completed cards
- Locked cards: `aria-disabled="true"`, no tabIndex, no role="button"
- Active card: `aria-label="{title} — in progress"`, `tabIndex={0}`, `role="button"`
- Gate banner: `role="status"` so screen readers announce the frozen state without focus management
- VaultPage entry card: `aria-label="Daily Photos — answer 3 photo prompts together, once a day"` (matches existing VaultPage card aria-label pattern)
