## Component Inventory

These are the new components Phase 10 introduces. All built with inline styles following the existing pattern.

### PhotoCaptureInput

A reusable component that accepts a `prompt` string and an `onPhotoSubmit(file, caption)` callback.

**Anatomy:**
1. Prompt text — rendered in Patrick Hand 16px at top of component
2. Photo trigger area — dashed-border rectangle (matches empty cork board slot pattern from VisionTab) when no photo selected; shows preview image after selection
3. Two trigger buttons — "Take Photo" (opens `capture="environment"` input) and "Choose from Gallery" (opens standard file input). Both are `<label>` elements wrapping hidden `<input type="file">`.
4. Photo preview — polaroid frame: white background, 6px top/side padding, 22px bottom padding (matches VisionTab CorkBoardSlot polaroid exactly)
5. Caption input — torn-paper style area below photo preview (see TornPaperCaption section)
6. Submit button — `.btn .btn-primary` "Add this photo" — disabled until photo selected
7. Retake Photo / Remove Photo — small secondary action below photo preview, destructive color

**States:**
- `idle` — no photo, prompt + trigger buttons visible
- `photo-selected` — photo preview + caption input visible, submit enabled
- `uploading` — submit button shows spinner text "Saving...", button disabled, inputs disabled
- `success` — (handled by parent page — component unmounts or resets)
- `error` — inline error message below submit button (see Copywriting)

### TornPaperCaption

A caption input styled as a torn-paper strip below a photo.

**Visual treatment:**
- White background with `border: 1.5px solid var(--border-pencil)` on top/left/right
- Bottom edge uses `.torn-edge` mask (already defined in index.css)
- Input is a single-line `<input>` (not textarea) — maximum 80 characters
- Font: Caveat 13px, centered, color var(--text-secondary)
- Placeholder: "add a caption..." in italic
- Focus: bottom border transitions to var(--accent-coral) (matches .input pattern)
- Character count shown at bottom-right in Patrick Hand 14px (Label role), var(--text-light)

**Sizing:**
- Width: 100% of photo width
- Height: 40px (single line — no scrolling required, per PHOTO-03)
- Bottom torn-edge mask height: 18px (matches existing .torn-edge in index.css)

## Interaction Contracts

### Camera / Gallery Trigger

- Tapping "Take Photo" opens native camera via `<input type="file" accept="image/*" capture="environment">`
- Tapping "Choose from Gallery" opens native gallery via `<input type="file" accept="image/*">` (no capture attribute)
- Both inputs are visually hidden; triggers are styled `.btn .btn-secondary` labels
- After file selected: immediately show polaroid preview (compress client-side via canvas before upload — same `compressAndUpload` pattern as VisionTab)
- No crop UI — per out-of-scope: "Rely on device camera/gallery for editing"
- No drag-and-drop — mobile-first single-column layout, touch only

### Photo Preview

- Displayed in a polaroid frame matching VisionTab's CorkBoardSlot exactly:
  - `background: #fff`
  - `padding: 6px 6px 22px`
  - `boxShadow: 2px 3px 8px rgba(0,0,0,0.18)`
  - `borderRadius: 1px`
- Image fills width, height auto
- A small "✕ remove" button sits at top-right corner of the polaroid (18×18px, 50% radius, rgba(0,0,0,0.5) background, `aria-label="Remove photo"`) — tapping clears photo and returns to idle state

### Caption Input Focus Behavior

- Caption field is immediately visible after photo is selected (not hidden behind a tap)
- Keyboard appearance on mobile must not cause page scroll — component uses `position: relative` container so keyboard pushes the view up naturally
- `onBlur` autosaves caption to local state (not to DB — saved only on submit)
- Caption is optional — submit is enabled after photo selected, regardless of caption

### Upload / Submit

- On "Add this photo" tap: compress image to max 800px wide via canvas (reuse VisionTab's `compressAndUpload` helper), then upload to Supabase Storage
- Button text changes to "Saving..." during upload (no spinner graphic — text only, consistent with existing button patterns)
- Button is `disabled` and opacity 0.6 during upload
- On success: parent callback fires (`onPhotoSubmit`) — component state managed by parent page
- On error: inline error shown below button (see Copywriting)

### Accessibility

- Both trigger `<label>` elements have visible text ("Take Photo", "Choose from Gallery") — no icon-only buttons
- Photo preview `<img>` has `alt` set to caption text if present, else "your photo"
- Caption input has `<label>` with `htmlFor`/`id` association and visible label "Caption (optional)"
- Submit button is `<button type="button">` — never `<div>` or `<span>`
- Remove photo button has `aria-label="Remove photo"` (icon-only circle button — no visible text)
- All interactive elements receive focus ring (browser default — do not suppress outline)
