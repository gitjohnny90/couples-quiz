## Spacing Scale

Reuses the established 4/8/16/24/32/48/64 scale. No exceptions.

| Token | Value | Usage in photos tab |
|-------|-------|----|
| xs | 4px | Gap between card title and completion date line |
| sm | 8px | Border-radius on cards, small inner gaps |
| md | 16px | Card inner padding, empty state inner padding, card-list vertical gap (12px used for gap is OUT of scale — see exception) |
| lg | 24px | Empty state outer padding, top margin before card list |
| xl | 32px | Section breaks (unused in this tab — reserved) |

**Exception — card list gap:** The existing books-tab pattern uses `gap: 12` between cards. Phase 13 matches the existing pattern exactly for visual consistency with the other four tabs. `12` is NOT on the 4/8/16/24/32 scale but is established elsewhere in the JournalPage and considered legacy-consistent. **Any NEW spacing values introduced by Phase 13 MUST be on the 4-point scale.** The `gap: 12` is a reused pattern, not a new value.

**Exception — card padding:** Cards use `padding: '16px 18px'` matching the existing books tab. `18` is off-scale; it is a legacy reuse, not a new introduction. If the planner prefers strict compliance, swap to `padding: 16` — both are acceptable.

## Tab Switcher

### Change Location

`src/pages/JournalPage.jsx` line 222 — the inline `[[...],[...]]` array passed to `.map()`.

### Change

```js
// BEFORE:
{[['mc', 'quizzes'], ['dd', 'deep dive'], ['drawings', 'drawings'], ['books', 'books']].map(([key, label]) => ( ... ))}

// AFTER:
{[['mc', 'quizzes'], ['dd', 'deep dive'], ['drawings', 'drawings'], ['books', 'books'], ['photos', 'photos']].map(([key, label]) => ( ... ))}
```

### Tab Button

The button JSX is NOT modified. It is fully data-driven — the new `['photos', 'photos']` tuple picks up identical styles automatically. This means:
- `flex: 1` — 5 tabs now share width evenly (~72px each on 360px viewport minus gutters)
- Active state highlights with `--accent-coral` and `var(--bg-paper)` (unchanged)
- `fontSize: '0.95rem'` inherited legacy — NOT Phase 13's responsibility to fix

### Mobile Viewport Check (360px)

With 5 tabs at `flex: 1`, each button is ~65–72px wide after the 6px gap. Known risk: the `'deep dive'` label is the longest (9 chars). In testing:
- If `'deep dive'` wraps to 2 lines or truncates: acceptable — label remains legible. No change required.
- If it overflows the container: shorten ONLY the new tab to `'photos'` (already the shortest) OR keep and accept wrap.

**Contract decision:** Do NOT shorten any existing labels. The new tab label is `'photos'` (6 chars, shortest in the set). If wrapping occurs on `'deep dive'`, escalate to planner before touching existing labels — label changes are user-facing copy changes outside Phase 13's scope.

## Tab Body — Card List

Shown when `completedPhotoCards.length > 0`.

### Container

```js
<div style={{ display: 'flex', flexDirection: 'column', gap: 12 }}>
  {completedPhotoCards.map((card, i) => ( <PhotoJournalCard /> ))}
</div>
```

`gap: 12` is the legacy-reused value from the books tab. Acceptable exception — see Spacing.

### Sort Order

Newest first, by `completedAt` descending:

```js
.sort((a, b) => new Date(b.completedAt) - new Date(a.completedAt))
```

### Card Shape (per completed section)

```
┌──────────────────────────────────────┐
│ 🌞  Morning Routine               →  │   ← row: emoji | title+date | arrow
│     completed Apr 1                   │
└──────────────────────────────────────┘
```

### Card Element

| Property | Value |
|----------|-------|
| Wrapper | `<motion.div>` with `key={card.id}`, `className="glass"` |

| onKeyDown | Enter/Space → `e.preventDefault()` + same navigate |

```jsx
      fontSize: '0.875rem',
      color: 'var(--accent-sage)',

      margin: 0,
    }}>
      completed {new Date(card.completedAt).toLocaleDateString('en-US', { month: 'short', day: 'numeric' })}

    fontSize: '1rem',
    color: 'var(--text-light)',
    flexShrink: 0,

```

### Card Visual Notes

- **No thumbnail image.** Photos are stored in Supabase Storage and fetched as signed URLs (1 hour TTL). Pre-fetching a thumbnail for every completed section would trigger N parallel signed-URL requests on tab open — slow, wasteful, and unnecessary. The emoji is the section's visual signature. The reveal page does the signed-URL fetch when the user actually taps in.
- **No expandable accordion.** Unlike books/quizzes/deep dive tabs, tapping navigates away. Do NOT call `setExpandedItem`. Do NOT use the existing `expandedItem` state for photo cards.
- **Alternating rotation** (`-0.3deg` / `+0.3deg`) matches the hand-drawn notebook aesthetic used on every other tab.

## Data Binding

### Source

Single `responses` row:
- `pack_id: 'daily-photo-challenge'`
- `player_id: 'shared'`
- `answers.completedSections: { [sectionId]: ISO timestamp }`

### Extraction (inside existing fetchAll effect)

Add immediately after `setBookEntries(...)`:

```js
const photoChallengeRow = allResponses.find(
  r => r.pack_id === 'daily-photo-challenge' && r.player_id === 'shared'
)
setCompletedPhotoSections(photoChallengeRow?.answers?.completedSections ?? {})
```

### Card Derivation

```js
const completedPhotoCards = Object.entries(completedPhotoSections)
  .map(([sectionId, completedAt]) => {
    const section = photoSections.find(s => s.id === sectionId)
    if (!section) return null // defensive against deleted section IDs
    return {
      id: sectionId,
      title: section.title,
      emoji: section.emoji,
      description: section.description,
      completedAt,
    }
  })
  .filter(Boolean)
  .sort((a, b) => new Date(b.completedAt) - new Date(a.completedAt))
```

### Filter Extension (line 110)

Prevent photo rows from leaking into `mcResponses`:

```js
.filter(r =>
  !r.pack_id?.startsWith(DRAW_PACK_PREFIX)
  && r.pack_id !== 'study-together'
  && r.pack_id !== 'daily-photo-challenge'
  && r.pack_id !== 'daily-photo-section'
)
```

### Import

Add at top of `JournalPage.jsx`:

```js
import photoSections from '../data/photoSections'
```

| Event | Behavior |
|-------|----------|

| User taps a completed section card | `navigate(\`/daily-photo-reveal/${sessionId}/${card.id}\`)` |

## Data Shape Caveat (cross-phase, planner must confirm)

Phase 13's research surfaced an open question about whether per-player rows at `pack_id='daily-photo-section'` persist across multiple completed sections, or whether each new completion overwrites the previous. If the latter, tapping an older completed card will land on the reveal page and show "Photos aren't ready yet" — violating JRNL-02.

**This is NOT a UI-SPEC concern.** The UI contract is: tapping a card navigates to `/daily-photo-reveal/:sessionId/:sectionId`. What the reveal page then displays is governed by the reveal page's own logic and the underlying data shape.

**Planner responsibility:** Verify via `.planning/phases/13-journal-integration/13-RESEARCH.md` Open Question #1 before executor starts. If the bug reproduces, a schema fix precedes the journal tab work. If not, proceed as specified.

The UI-SPEC is correct either way — the card list, empty state, and navigation contract do not change based on the data shape fix.
