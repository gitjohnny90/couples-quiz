<objective>
Fix the blocker where a partner's invite code is lost when email confirmation opens in a different browser/device, causing them to silently get a new solo session instead of joining their partner's session.

Purpose: pendingInviteCode lives only in localStorage, which is per-browser. When email confirmation opens in a different context, the code is gone and HomePage falls through to autoCreate(). The fix persists the invite code in Supabase user metadata (survives cross-device) and adds a manual "join with code" recovery option.
Output: Invite code survives cross-device email confirmation. Users without a code see a join option instead of silent session creation.
</objective>
