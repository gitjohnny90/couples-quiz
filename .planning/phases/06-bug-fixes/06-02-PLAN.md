**BUG-02 — VisionTab caption autosave (src/pages/VisionTab.jsx)**

In `handleBoardCaption` (around line 159), the debounced save closes over the stale `data` variable:

```js
const handleBoardCaption = (slotIndex, caption) => {
    const board = [...(data.board || [])]
    const idx = board.findIndex(b => b.slot === slotIndex)
    if (idx >= 0) {
      board[idx] = { ...board[idx], caption }
      setData(prev => ({ ...prev, board }))
      clearTimeout(captionTimeout.current)
      captionTimeout.current = setTimeout(() => saveData({ ...data, board }), 800)
      //                                              ^^^^^^ stale closure!
    }
  }
```

The `data` in the setTimeout callback is captured when `handleBoardCaption` runs, not when the timeout fires 800ms later. If the user edits multiple captions quickly, earlier edits can overwrite later ones.

Fix: Use a ref to hold the latest data, so the timeout always reads current state.

1. Add a `dataRef` near existing refs:
   ```js
   const dataRef = useRef(data)
   ```

2. Keep `dataRef` in sync with `data` state. Add after the existing `useEffect` that sets `mountedRef`:
   ```js
   useEffect(() => { dataRef.current = data }, [data])
   ```

3. Update `handleBoardCaption` to read from the ref inside the timeout:
   ```js
   const handleBoardCaption = (slotIndex, caption) => {
     const board = [...(data.board || [])]
     const idx = board.findIndex(b => b.slot === slotIndex)
     if (idx >= 0) {
       board[idx] = { ...board[idx], caption }
       setData(prev => ({ ...prev, board }))
       clearTimeout(captionTimeout.current)
       captionTimeout.current = setTimeout(() => {
         const currentBoard = [...(dataRef.current.board || [])]
         const ci = currentBoard.findIndex(b => b.slot === slotIndex)
         if (ci >= 0) currentBoard[ci] = { ...currentBoard[ci], caption }
         saveData({ ...dataRef.current, board: currentBoard })
       }, 800)
     }
   }
   ```

4. Apply the same ref pattern to `handleNorthStarChange` (line ~120) which has the same stale closure issue:
   ```js
   const handleNorthStarChange = (text) => {
     const updated = { ...data, northStar: text }
     setData(updated)
     clearTimeout(northStarTimeout.current)
     northStarTimeout.current = setTimeout(() => saveData({ ...dataRef.current, northStar: text }), 800)
   }
   ```

**BUG-03 — PredictPartnerPage post-save check (src/pages/PredictPartnerPage.jsx)**

After saving answers (around line 220-227), the code calls `await fetchResponses()` then immediately checks `allResponses[activePack.id]` — but `fetchResponses` updates state via `setAllResponses`, which is async. The check reads the OLD `allResponses` from the closure.

```js
await fetchResponses()
// allResponses is still the OLD value here!
const partnerData = allResponses[activePack.id]?.[partnerId]
if (partnerData?.responses?.length === 3) {
  setScreen('reveal')
} else {
  setScreen('waiting')
}
```

Fix: Have `fetchResponses` return the fetched data so the caller can use it directly.

1. Modify `fetchResponses` to return the mapped data:
   ```js
   const fetchResponses = useCallback(async () => {
     // ... existing fetch logic ...
     setAllResponses(mapped)
     return mapped   // <-- add this return
   }, [sessionId])
   ```

2. Update the post-save block (around line 220) to use the returned data:
   ```js
   const freshData = await fetchResponses()
   const partnerData = freshData?.[activePack.id]?.[partnerId]
   if (partnerData?.responses?.length === 3) {
     setScreen('reveal')
   } else {
     setScreen('waiting')
   }
   ```
