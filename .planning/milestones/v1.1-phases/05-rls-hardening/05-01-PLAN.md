  <action>
Create a SQL migration file that replaces the existing FOR ALL policies on all 9 feature tables with per-operation policies that enforce player_id ownership on writes.

**For each of the 9 feature tables** (responses, profiles, deep_dive_responses, shared_items, love_notes, reactions, predict_partner, finish_sentence, hot_takes):

1. DROP the existing "partners_access_data" policy (from supabase-rls-fix.sql)
2. Create a SELECT policy (unchanged — session membership only via user_sessions)
3. Create an INSERT policy with WITH CHECK that enforces BOTH:
   - session_id membership (via user_sessions)
   - player_id matches the authenticated user's player_id (via subquery joining user_sessions)
4. Create an UPDATE policy with USING + WITH CHECK enforcing the same
5. Create a DELETE policy with USING enforcing session membership + player_id match

**Player_id resolution subquery** (use this pattern):
```sql
player_id = (
  SELECT us.player_id FROM public.user_sessions us
  WHERE us.user_id = (SELECT auth.uid())
    AND us.session_id = <table>.session_id
)
```

**Special cases to handle:**
- **responses**: player_id can be 'game' (tic-tac-toe shared state) or 'shared' (study-together). For these rows, BOTH partners must be able to write. Add an OR clause: `OR player_id IN ('game', 'shared')` to the INSERT/UPDATE WITH CHECK.
- **shared_items**: Uses `added_by` column instead of `player_id`. The enforcement column is `added_by` for INSERT, but UPDATE/DELETE should allow both partners (either partner can rate/update status on shared movies). So for shared_items: INSERT enforces `added_by` matches player_id, UPDATE/DELETE use session membership only.
- **reactions**: Already has per-operation policies in supabase-rls-policies.sql. Drop those too and recreate with player_id enforcement on INSERT/UPDATE (reaction.player_id must match user's player_id).

**Type fix (SEC-11):** For finish_sentence and hot_takes, ensure ALL policy clauses use `session_id::text` on the left-hand side (matching the `::text` cast in the subquery). This fixes the uuid/text comparison mismatch from supabase-rls-fix.sql.

**Performance:** All `auth.uid()` calls must use `(SELECT auth.uid())` for initPlan optimization.

**Wrap each table's DROP + CREATE statements in BEGIN/COMMIT** for atomicity (same pattern as supabase-rls-policies.sql).

Add a header comment explaining this migration adds player_id enforcement on top of session membership, and fixes the finish_sentence/hot_takes type cast.
